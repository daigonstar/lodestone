# Security review, 22 November 2026

**Scope:** Lodestone 0.1.1 (the Rust backend in `src-tauri/`, the interface in `ui/`, the Flatpak and the
release tooling). Done with an AI coding assistant (Claude) and reviewed by the maintainer.
**Fixes ship in:** 0.1.2 (findings 1 to 7); finding 8 shipped in 0.1.1.

Severity uses a simple scale: **High** (an outsider can take over or read secrets without the user doing
anything unusual), **Medium** (a real path to harm that needs a specific situation, such as a malicious
mod listing or a vulnerable library), **Low** (limited harm or hard to reach), **Hardening** (no known way
to exploit it, but it removes a safety net).

## Findings

### 1. Vulnerable SQLite library: Medium, fixed
- **What:** the bundled SQLite (crate `libsqlite3-sys` 0.30.1, through `rusqlite` 0.32) had a published
  vulnerability, [RUSTSEC-2026-0459](https://rustsec.org/advisories/RUSTSEC-2026-0459) (SQLite
  CVE-2026-119375). Lodestone uses SQLite to read Battle.net's and Lutris's database files.
- **Fix:** `rusqlite` 0.43 (`libsqlite3-sys` 0.40).
- **Checked:** `cargo audit` reports no vulnerabilities; all tests pass; Battle.net's real account
  database still reads correctly.

### 2. Mod downloads could be written outside the instance folder: Medium, fixed
- **What:** when installing a Minecraft mod, the file was saved under the name Modrinth's or CurseForge's
  answer gave, joined straight onto the mods folder. A malicious or compromised listing with a name like
  `../../.config/autostart/x.desktop` could have written a file elsewhere in the home folder, including
  somewhere that runs at login.
- **Fix:** `safe_file_name()` in `src-tauri/src/mc/platforms.rs` refuses any name with a folder separator,
  a leading dot, `..`, control characters or a NUL, for installs and updates.
- **Checked:** unit test `refuses_file_names_that_leave_the_folder`.

### 3. Steam Web API key could appear in error messages: Low, fixed
- **What:** the Steam Web API takes the key in the address (`?key=`). Errors from a service already had
  the address trimmed, but connection errors (offline, timeout, TLS) include the full address, key and
  all, and were shown in the app's messages and the Friends panel.
- **Fix:** `net::err` now replaces the query part of every web address in an error with `?…`
  (`hide_queries`). EA and Ubisoft errors go through it too.
- **Checked:** unit test `hides_keys_in_error_messages`.

### 4. No content security policy in the main window: Hardening, fixed
- **What:** the interface had no CSP. All outside data was already escaped (no injection was found),
  but if an escaping mistake ever slipped in, a script injected through a game title or news item could
  have used the app's commands, which include starting programs.
- **Fix:** a strict CSP in `tauri.conf.json`: only the app's own script files run (no inline scripts or
  handlers, no `eval`), the page can only talk to the app itself, and nothing can be framed or embedded.
  The 18 inline `onerror`/`onclick` handlers were replaced with code in `app.js`, and HTML escaping now
  also covers single quotes.
- **Checked:** no CSP violations in the interface under the same policy; the real app loads the library,
  local and remote artwork, dialogs and broken-image handling as before.

### 5. Image addresses in CSS weren't fully escaped: Low, fixed
- **What:** artwork addresses placed in `background-image:url('…')` were HTML-escaped only, which CSS
  undoes, so an address containing `')` could have added its own CSS (for example loading a tracking
  image). It couldn't run scripts.
- **Fix:** `cssUrl()` percent-encodes quotes, brackets, backslashes and spaces in those addresses.
- **Checked:** escaping checked in the interface.

### 6. Sign-in windows accepted the token hand-off from any page: Low, fixed
- **What:** EA, Ubisoft, Epic and GOG sign-in windows pass the result back to Lodestone through an internal
  address. Any page shown in the window (sign-in providers, links on the store's pages) could have used it
  to hand Lodestone a different account's session. None of the user's data would have leaked; Lodestone
  would have shown the other account's games.
- **Fix:** the hand-off is only accepted straight from the store's own sign-in pages (`*.ea.com`,
  `*.ubisoft.com`/`*.ubi.com`, `*.epicgames.com`, `*.gog.com`).
- **Checked:** builds and tests pass. **Not yet checked with a live sign-in for each store;** this is
  listed under "Still to do" below.

### 7. Downloaded tools weren't checked against a checksum: Low, fixed
- **What:** umu-launcher, legendary, gogdl and MangoHud are downloaded from their official GitHub
  releases over HTTPS and then run, without checking the file itself.
- **Fix:** each download is checked against the SHA-256 checksum GitHub publishes for the release file,
  and refused if it doesn't match (`net::verify_release_file`). Release files uploaded before GitHub kept
  checksums are accepted as before; all four tools' current releases have one.
- **Checked:** unit test `checks_release_files_against_githubs_checksum`.

### 8. Epic and GOG sign-in files were readable by other users: Medium, fixed in 0.1.1
- **What:** legendary and gogdl write their token files with ordinary permissions, so other accounts on
  the same PC could read the Epic and GOG sessions.
- **Fix:** Lodestone keeps those folders `700` and files `600`, checked at start and whenever it loads the
  library (`state::lock_down_secrets`), and writes GOG's file privately itself.
- **Checked:** permissions confirmed on a real install.

## Looked at and found fine

- **Remote pages can't use the app.** Store pages, sign-in windows, Workshop and news pages open in their
  own web views with no app permissions; Tauri 2 blocks app commands from remote addresses by default.
- **Link opening:** `open_url` and `open_page` only open `http(s)` addresses, so a bad link can't open a
  local file or another program.
- **Interface escaping:** every place outside data (titles, news, mod details, friends' names, Wikipedia
  text) is put into the page is escaped.
- **Logs:** launch logs and the EA sign-in log contain no tokens, codes or passwords (the sign-in log
  records only scheme, host and path).
- **Artwork files** are named by Lodestone (letters and digits only), not by the download.
- **Network destinations:** all 42 addresses in the code are listed in `network-hosts.txt`, now checked
  on every push.

## Known and accepted for now

- **Warnings from Tauri's GTK libraries:** `glib` 0.18 (RUSTSEC-2024-0429, unsound iterator), and the
  unmaintained `proc-macro-error` and `chrono`. They come with Tauri's GTK 3 stack and can't be upgraded
  until Tauri moves on. None is a known vulnerability in how Lodestone uses them.
- **Epic games get a one-time sign-in code on their command line.** That's how Epic games start (through
  legendary, as through Epic's own launcher); other programs running as the same user can see it.
- **Store installers** (Battle.net, EA app, Ubisoft Connect, Guild Wars 2) are downloaded over HTTPS from
  their publishers, who don't publish checksums to check against.
- **The interface can show image files from anywhere in your home folder** (Tauri's asset access), so it
  can display covers from Steam, Heroic, Lutris and files you pick. The CSP stops pages sending data
  anywhere else.
- **The Flatpak has host access**, because it runs games, Steam and Proton on your system.
